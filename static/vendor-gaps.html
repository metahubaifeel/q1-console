判定口径。「能调」= 真建 client、spin 到图谱稳定后 service_is_ready() 为真； 只看 ros2 service list 里有名字是不算的，这台机器上两者差别很大。 同理话题的「有发布者」是暖机 11.6 秒、数字不再增长之后才数的 —— 建完节点立刻数会把 /aima/hal/audio/capture 这种活得好好的话题数成 0 个发布者。

P0

卡住功能，不做就等于少一块

这四条直接决定总控台上有没有东西可看、可点。

01全身关节状态缺失，数据孪生只能画上半身

现象

机器人唯一在发的关节状态话题是 /upper_body_joint_states， 里面只有 10 个关节：左右肩 pitch/roll/yaw、左右肘、腰 roll、腰 yaw。

两条腿的髋/膝/踝、脖子、手腕、腰 pitch —— 一个都没有。 同时 /tf 里只有一条变换：odom → base_link， 没有任何肢体坐标系，所以也没法从 TF 树补回来。

结果就是孪生体只能显示底盘位姿加两条胳膊，腿部永远是初始姿态 —— 用户看到的是一个「站着不动腿」的机器人。

证据

/aima/hal/joint/state（aimdk_msgs/msg/JointStateArray） 已经声明，但发布者数量为 0。这条正是会带全身关节的那条。

要什么

发布 /aima/hal/joint/state，或另行指定一条全身关节状态话题 （含关节名 + 位置，最好带速度/力矩）；并给出完整的 TF 树， 至少覆盖 base_link → 各连杆。

02导航 / 建图 / SLAM 整条栈没有在跑

现象

四个状态话题的发布者全是 0： /aima/algo/navi/state、/aima/map/state、 /aima/map/build_state、/slam_state。 服务侧 GetMapList 广告了出来但无人 serve。

所以总控台上的「房间图 / 雷达扇区 / 导航点」三块只能是空的 —— 不是接线问题，是这台机器当前没加载这些能力。

要什么

提供启动导航栈的方式（哪个服务/脚本、什么前置条件）， 并把 GetMapList 等一系列地图服务 serve 起来。 另外请说明建图与定位分别怎么进、怎么退。

03雷达 / 激光 / 点云在 ROS 图里完全看不到

现象

80 个话题里，唯一能匹配到 scan 的是 /robot/scan/bluetooth（蓝牙扫描，跟测距无关）。 没有任何 /scan、/points、/livox/*、 深度点云一类的话题。

要什么

说明测距数据从哪出：话题名、消息类型、坐标系、频率； 如果传感器存在但走的是非 ROS 通路，也请说明怎么取。 这是「雷达图」这一类界面能不能做的前提。

04表情与灯光的三个服务无人 serve

现象

PlayLight、SetNeckLight、PlayEmotionByStr 三个服务广告在图上，但都没有 server；配套的 /aima/hal/neck_light/state 也没有发布者。 目前只有 LedStripCommand 是通的，而它覆盖不到颈部灯。

要什么

把这三个 serve 起来，或明确告知替代接口。 脖子灯是这台机器最直观的状态显示位，缺了很可惜。

P1

影响体验与可维护性

不挡功能，但会让控制台显得残缺，或者出问题时无从下手。

05自录动作没有编号，播放通路要资源路径

现象

GetCustomMotionList 能调通（实测库里确有 1 条自录动作）， 但播放通路按接口文档填参数实调 PlayCustomMotion 返回 code=5 INVALID，动作一次都没播出来。 内置动作走 SetMcPresetMotion + 编号（3001–3051，实测 16 个）是通的； 两条路的行为不一致，界面上那个「自录动作」按钮只能先禁掉。

要什么

给出 PlayCustomMotion 的完整调用约定： resource_path 该填什么形态（是列表返回的路径原文，还是要拼目录？ 要不要传动作编号？）、code=5 的确切含义与触发条件、 和 SetMcPresetMotion 是否互斥、播完有没有回调。

06麦克风阵列选路恒为 0

现象

采集口是 48 kHz / 8 声道交错：前 6 路是麦克风，后 2 路是回采参考。 但 GetMicSourceRequest 返回的选路恒为 0， 没有波束成形或降噪档位可选。机器人说话时对讲里能听到自己的回声。

要什么

开放 SetMicSourceRequest 的可用取值与语义 （指向哪一路、是否启用波束成形/降噪），以及各档位的适用场景。

07舵机状态与跌倒预警区域拿不到

现象

/aima/hal/servo/state（ServoStatus）和 /fall_guard/danger_regions（PoseArray） 都声明了但没人发。后者尤其在意 —— 危险区域本来是可以在控制台上直观画出来的安全信息。

要什么

发布这两条；danger_regions 请说明坐标系与区域语义。

08各 SoC 的进程信息没有，负载高时无从定位

现象

/aima/hds/process/info/soc0、soc1、soc2 三条都无人发布。而这台机器实测长期 CPU 89–95%、负载 20–36、 平衡控制器 mc_main 常年 78–99%，Agent 进程常驻约 150% CPU / 1.5 GB。 我们知道「很挤」，但看不到是谁在挤。

要什么

发布这三条进程信息，或提供任何可查询各 SoC 负载/进程的接口。 对我们来说，这是「机器人为什么偶尔站不稳」最直接的线索。

10整块能力都是静默的

现象

自动充电：/aima/algo/charge_point/recognition_state、 /aima/algo/charge_point/sit_state 均无人发布。

附录 A

怎么复现

下面每条都是在这台机器上跑过的。所有命令都需要机器人自己的 DDS profile。

# 机器人上每个 ROS 进程都带这个 profile（见 /robot/software/*/bin/em_run.sh）。
# 不带的话会出现「服务名看得见、却永远匹配不上」的假象。
export FASTRTPS_DEFAULT_PROFILES_FILE=/robot/software/entry/cfg/standard/ros_dds_configuration.xml
source /opt/ros/humble/setup.bash

# ① 服务：广告 ≠ 能调。暖机到图谱稳定再逐个判。
python3 - <<'PY'
import rclpy, time
from rclpy.node import Node
from rosidl_runtime_py.utilities import get_service
rclpy.init(); n = Node("probe")
cli = {}
for s, ty in n.get_service_names_and_types():
    if ty and not s.startswith(("/probe", "/q1_")):
        try: cli[s] = n.create_client(get_service(ty[0]), s)
        except Exception: pass
last, stable, t0 = -1, 0, time.time()
while time.time() - t0 < 40:
    rclpy.spin_once(n, timeout_sec=0.5)
    ok = sum(1 for c in cli.values() if c.service_is_ready())
    stable = stable + 1 if ok == last else 0
    if stable >= 6 and ok: break
    last = ok
print("可调", sum(1 for c in cli.values() if c.service_is_ready()), "/", len(cli))
print("无 server:", sorted(s for s, c in cli.items() if not c.service_is_ready()))
PY

# ② 话题：同样要暖机，否则活的话题会被数成 0 个发布者。
python3 - <<'PY'
import rclpy, time
from rclpy.node import Node
rclpy.init(); n = Node("probe")
last, stable, t0 = -1, 0, time.time()
while time.time() - t0 < 60:
    rclpy.spin_once(n, timeout_sec=0.5)
    live = sum(1 for t, _ in n.get_topic_names_and_types() if n.count_publishers(t))
    stable = stable + 1 if live == last else 0
    if stable >= 8: break
    last = live
print("无发布者:", [t for t, _ in n.get_topic_names_and_types() if not n.count_publishers(t)])
PY

三个坑，我们踩过，写在这里省贵方时间。 一是判定只能靠 service_is_ready()，ros2 service list 里出现名字不代表有人在 serve； 二是任何计数都要先暖机 —— 建完节点立刻数，DDS 还没发现完， 这台机器上会把活得好好的话题数成 0。 三是 QoS：/aima/hal/audio/capture 这类口用订阅端默认的 RELIABLE 会一条都收不到且不报错，必须 BEST_EFFORT；而个别话题（如 /aima/hal/touch/state）即便逐 QoS 试也只在事件发生时出数 —— 订阅端 QoS 请以逐话题实测为准，不要按 DDS 理论表猜。
